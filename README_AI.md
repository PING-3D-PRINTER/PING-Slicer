# PING Slicer：給 AI 助理的使用說明（v0.3）

> 讀者是**客戶電腦上的 AI 助理**（Claude Code、Codex 等會跑指令的 AI）。
> 讀完這份，你可以替使用者完成：**STL → 用 PING Slicer 切片 → 上傳到 PING 3D 列印機**。
> 不需要開 PING Slicer 的視窗，全程用命令列。
>
> 適用：PING Slicer V3.6.x（Windows）廠內測試版。已實測：FD300＋0.4 噴嘴＋PLA（含有懸空、會長支撐的模型）。其他機型照同樣的方法做，但還沒逐一實測；遇到和本文不符的情況，照實告訴使用者。

## 0. 安全規則（一定要遵守）

1. **絕不開始列印**，除非使用者在這次對話中明確說「開始列印」。上傳檔案到機台 ≠ 開始列印。開始列印前要提醒使用者：平台清空、料已裝好、人在機台旁。
2. **不修改 PING Slicer 安裝目錄與 `%APPDATA%\PingSlicer` 裡的任何檔案。** 要改參數就複製一份到你自己的工作資料夾再改。
3. 機台上只上傳 gcode 檔，**不改機台設定（config）、不重啟、不送加熱或移動指令。**
4. 不確定機型、噴嘴口徑、材料時，**問使用者，不要猜**。參數選錯一樣會切出檔案、也印得出來，但品質會不對。

## 1. 找到切片程式

- 執行檔名稱：`ping-slicer.exe`。常見位置：使用者解壓縮的資料夾（例如 `D:\PING-Slicer-portable\`）或 `C:\Program Files\PING Slicer\`。找不到就問使用者裝在哪。
- 版本確認：切完的 gcode 第 2 行會寫 `; generated by OrcaSlicer x.y.z (PING Slicer X.Y.Z)`。
- ⚠ `ping-slicer.exe --help` **什麼都不會印**（Windows 視窗程式會吞掉文字輸出）。這不代表沒有命令列功能，照第 4 節的指令直接跑即可。

## 2. 選參數檔

參數檔是 JSON，放在兩個地方之一（**第一個存在就用第一個**，那是使用者軟體實際在用的版本）：

1. `%APPDATA%\PingSlicer\system\PING\`
2. `<安裝目錄>\resources\profiles\PING\`

底下有三個子資料夾，各選一個檔：

| 種類 | 子資料夾 | 檔名規則 | 範例 |
|---|---|---|---|
| 機器 | `machine\` | `<機型> <口徑> nozzle.json` | `FD300 0.4 nozzle.json` |
| 製程 | `process\` | `<層高>mm [變體] @<機型> (<口徑>).json` | `0.2mm 易拆 @FD300 (0.4).json` |
| 線材 | `filament\` | `PING <材料> ....json` | `PING PLA - 220.json` |

選法：

1. **機型＋口徑**：問使用者（例如「FD300、0.4 噴嘴」）。機台的資訊也可以從第 6 節的 Moonraker 查，但口徑通常查不到，要問。
   - PING 機型命名：F＝FAST 高速、D＝雙噴頭、P＝單噴頭、字尾 F＝四噴頭、數字＝列印直徑 mm、Pro＝進階款、E＝資安版。
   - 機型名後面有「同進」「單料頭」「照片磚」字樣的是特殊模式，使用者沒提就用**不帶這些字的那一個**。
2. **製程與線材：先用機器檔裡的預設值。** 打開機器檔，讀：
   - `default_print_profile` → 製程檔名（不含 `.json`）
   - `default_filament_profile` → 線材檔名清單，**只取第一個**（見第 5 節限制）
   - 使用者指定了別的材料（例如 PETG）或層高，就在對應資料夾找同機型、同口徑的檔；有好幾個候選時列給使用者選。
3. 線材檔裡的 `compatible_printers_condition` 寫了它適用哪類機器；含 `CLASSIC` 的是前代機型用的，`PHOTOTILE` 是照片磚專用，一般機型不要選這兩類。

## 3. 攤平參數檔（必做）

製程與線材檔用 `inherits` 繼承同資料夾裡的父檔，**只給子檔會缺參數，切片會失敗或結果不對**。要先把繼承鏈攤平成一個完整的檔，並把 `compatible_printers` 填成你選的機器名。

把下面這段存成 `flatten.py`，改最上面五行後執行（需要 Python 3）：

```python
import json, os
PROFILES = os.path.expandvars(r"%APPDATA%\PingSlicer\system\PING")  # 第 2 節找到的資料夾；不存在就改成 <安裝目錄>\resources\profiles\PING
MACHINE  = "FD300 0.4 nozzle"
PROCESS  = "0.2mm 易拆 @FD300 (0.4)"
FILAMENT = "PING PLA - 220"
OUTDIR   = r"D:\_ping_ai\profiles"   # 你自己的工作資料夾（路徑要短，見第 5 節）

def load(sub, name):
    d = json.load(open(os.path.join(PROFILES, sub, name + ".json"), encoding="utf-8"))
    if d.get("inherits"):
        base = load(sub, d["inherits"]); base.update(d); d = base
    return d

def flat(sub, name, extra=None):
    d = load(sub, name)
    for k in ("inherits", "setting_id", "instantiation"):
        d.pop(k, None)
    d["name"] = name
    d.update(extra or {})
    out = os.path.join(OUTDIR, sub + ".json")
    json.dump(d, open(out, "w", encoding="utf-8"), ensure_ascii=False, indent=1)
    return out

os.makedirs(OUTDIR, exist_ok=True)
compat = {"compatible_printers": [MACHINE]}
# 只載一支線材時，把支撐與擦料塔指到第 1 支，讓 gcode 裡記錄的設定和實際一致（切片器本來就會改用第 1 支，這行不改變列印路徑）
single = {"support_filament": "1", "support_interface_filament": "1", "enable_prime_tower": "0"}
print(flat("machine", MACHINE))
print(flat("process", PROCESS, {**compat, **single}))
print(flat("filament", FILAMENT, compat))
```

## 4. 切片

寫成**一行**（cmd、PowerShell、Git Bash 都適用；Git Bash 下路徑可改用正斜線 `D:/...`；PowerShell 要在最前面加 `&`）：

```
"<安裝目錄>\ping-slicer.exe" --slice 0 --load-settings "D:\_ping_ai\profiles\machine.json;D:\_ping_ai\profiles\process.json" --load-filaments "D:\_ping_ai\profiles\filament.json" --outputdir "D:\_ping_ai\out" "<模型>.stl"
```

- 模型路徑含中文沒問題。

- 機器檔和製程檔放在**同一個引數**裡、用分號 `;` 隔開；線材另用 `--load-filaments`。
- 成功時 exit code 為 0，產出 `<outputdir>\plate_1.gcode`。模型會自動放在平台中央。
- log 出現 `[error] Invalid T command (T1)` 是正常的：雙噴頭機型（例如 FD300）的起始 gcode 會讓兩個噴頭都預擠一次，而你只載了一支線材。雖然標成 error，但不影響產出，gcode 開頭的 `T1`／`T0` 也要保留。
- 失敗對照：`process not compatible with printer` ＝ 第 3 節的 `compatible_printers` 沒填對；exit 139 且沒訊息 ＝ 踩到第 5 節的限制。

切完先自己檢查 gcode，再回報給使用者。下面後兩項在檔尾附近（約最後 100 行內，不是最後幾行），要用搜尋（grep／Select-String）找，不要只看 tail：

- 第 2 行的 PING Slicer 版本。
- `; estimated printing time (normal mode) =` 與 `; total filament used [g] =`（預估時間與用料）。
- `; printer_settings_id`、`; print_settings_id`、`; filament_settings_id` 是不是你選的那三個。

## 5. 已知限制

- **一次只能載一支線材**。`--load-filaments` 給兩支以上會直接當掉（exit 139）。多色、多材料、照片磚請使用者開視窗版切。
- **只吃 STL／OBJ／AMF**，不吃 STEP。STEP 請使用者先在視窗版匯入，或用其他工具轉成 STL。
- **不執行後處理腳本**（`post_process`）。
- `--outputdir`、`--datadir` 不要放在很長的路徑下（會當掉），用 `D:\_ping_ai\...` 這類短路徑。
- 不要用 `--scale`（會當掉）；要縮放請先自己產出縮放後的 STL。

## 6. 上傳到機台（Moonraker）

PING 機台跑 Klipper＋Moonraker，在區域網路上用 HTTP 存取，通常不需要密碼。資安版（機型名含 E）可能需要認證：連線被拒（401／403）時請使用者提供 API key，放在 `X-Api-Key` 標頭；這部分尚未實測。**機台 IP 問使用者**（機台螢幕的網路頁面看得到）。

1. **先確認機台空閒**：

   ```
   GET http://<IP>/printer/objects/query?print_stats
   ```

   `result.status.print_stats.state` 要是 `standby`、`complete` 或 `cancelled`。如果是 `printing` 或 `paused`，告訴使用者機台正在列印，可以照樣上傳（不影響列印中的工作），但不要做任何其他動作。

2. **上傳**（multipart/form-data）：

   ```
   POST http://<IP>/server/files/upload
     file = <gcode 檔>      （欄位名 file）
     root = gcodes
     path = <子資料夾，可省略>
   ```

   - 檔名用使用者看得懂的名字（例如 `零件A_PLA_0.2mm.gcode`）。檔名有中文時，用 Python（`requests` 或 `urllib`）送，**不要用 Windows 的 `curl -F`**：中文檔名會靜默失敗、回傳空內容。
   - 回應會有 `"action": "create_file"` 與檔案路徑。
   - 中文檔名在終端機上可能顯示成亂碼，那是顯示編碼的問題、不是檔名壞了。要核對時用 `response.json()` 解析、以 UTF-8 輸出，或用 `GET /server/files/directory?path=gcodes/<子資料夾>` 列檔。

3. **確認上傳成功**：

   ```
   GET http://<IP>/server/files/metadata?filename=<子資料夾/檔名>
   ```

   回傳裡有 `estimated_time` 就代表機台已經讀到這個檔。單位：`estimated_time`＝**秒**、`filament_total`＝**mm**、`filament_weight_total`＝**g**。換算後跟第 4 節的預估值對照（應該一致），再回報給使用者。

4. **開始列印**（只有使用者明確要求時，見第 0 節）：

   ```
   POST http://<IP>/printer/print/start?filename=<子資料夾/檔名>
   ```

## 7. 回報給使用者的內容

- 用了哪台機型、口徑、製程、線材，以及 PING Slicer 版本。
- 預估列印時間（換算成時／分）與用料（g），並說明切片端與機台端讀到的數字是否一致。
- 上傳到哪台機台（IP）、機台上的檔名。
- 「檔案已上傳、**尚未開始列印**」，並說明要開始時在機台螢幕上選檔，或由使用者明確叫你開始。
